# LoomQ QX · 自定义量子 RISC-V 扩展指令规格

## 为什么要有这个扩展

`compile_hybrid` 按契约返回两样东西：量子操作序列，和经典控制的 RISC-V 汇编。
两者之间的测量结果由评测系统注入寄存器——也就是说，程序自己是接不上的，
中间必须有一个外部搬运工。

QX 扩展把这一步取消：量子操作变成同一条指令流里的指令，`qmeas` 直接把测量结果
写进 `x(10+k)`，经典块随后从那里读。题面描述的 `c[k] → x10, x11, ...` 约定，
从"外部注入"变成"程序自己做的事"，一个模拟器跑完整个混合程序。

把量子比特下标放在**寄存器**而不是立即数里，是这个设计里唯一一处刻意的选择：
这样经典代码可以算出要操作哪个比特，混合编程才不只是"先量子后经典"两段拼接。

## 指令编码

自定义指令占用 RISC-V 保留的 **custom-0** 主操作码：

```
opcode = 0b0001011  (0x0B)
```

全部采用 R 型布局：

```
 31        25 24     20 19     15 14    12 11      7 6         0
┌────────────┬─────────┬─────────┬────────┬─────────┬───────────┐
│   funct7   │   rs2   │   rs1   │ funct3 │   rd    │  opcode   │
│   7 bits   │  5 bits │  5 bits │ 3 bits │  5 bits │  7 bits   │
└────────────┴─────────┴─────────┴────────┴─────────┴───────────┘
```

### funct3：指令类别

| funct3 | 类别 | 含义 |
|---:|---|---|
| `0b000` | QINIT | 分配 rs1 个量子比特，状态置 \|0…0⟩ |
| `0b001` | QGATE1 | 单比特无参门，比特下标在 rs1 |
| `0b010` | QGATE1P | 单比特含参门，比特在 rs1，角度在 rs2 |
| `0b011` | QGATE2 | 两比特无参门，比特在 rs1、rs2 |
| `0b100` | QGATE3 | 三比特门，控制位在 rs1、rs2，**目标位在 rd** |
| `0b101` | QMEAS | 测量 rs1 号比特，结果（0/1）写入 rd |
| `0b110` | QGATE2P | 两比特含参门，比特在 rs1、rs2，**角度在 rd** |

QGATE3 和 QGATE2P 借用 `rd` 字段当**源**操作数。R 型只有两个源寄存器字段，
而这两类指令需要三个输入；它们都不写回通用寄存器，所以 `rd` 空着，正好用上。

### funct7：具体门

| funct7 | QGATE1 | QGATE1P | QGATE2 | QGATE2P | QGATE3 |
|---:|---|---|---|---|---|
| `0x00` | H | RZ | CX | CU1 | CCX |
| `0x01` | X | RY | SWAP | — | — |
| `0x02` | S | U1 | — | — | — |
| `0x03` | S† | — | — | — | — |
| `0x04` | T | — | — | — | — |
| `0x05` | T† | — | — | — | — |

### 角度编码

含参门的角度以**定点整数**放在寄存器里：

```
寄存器值 k   表示角度   θ = k · π / 1024
```

取 1024 是因为分辨率 π/1024 远小于任何评测会用到的角度间隔，而且 k 落在
32 位有符号范围内绰绰有余。`riscv_emulator_qx.angle_units(θ)` 和
`units_to_angle(k)` 是这条换算的实现。

## 汇编助记符

| 助记符 | 操作数 | 语义 |
|---|---|---|
| `qinit rs1` | 比特数 | 分配并初始化 |
| `qh / qx / qs / qsdg / qt / qtdg rs1` | 比特下标 | 单比特门 |
| `qrz / qry / qu1 rs1, rs2` | 比特, 角度 | 含参单比特门 |
| `qcx rs1, rs2` | 控制, 目标 | 受控非 |
| `qswap rs1, rs2` | 比特, 比特 | 交换 |
| `qcu1 rs1, rs2, rd` | 比特, 比特, 角度 | 受控相位 |
| `qccx rs1, rs2, rd` | 控制, 控制, 目标 | Toffoli |
| `qmeas rd, rs1` | 结果寄存器, 比特 | 测量并坍缩 |

所有操作数都是寄存器，没有立即数形式。

### 编码示例

`qh x5`（对 x5 号比特施加 H）：

```
funct7=0x00  rs2=0  rs1=5  funct3=0b001  rd=0  opcode=0b0001011
= 0000000 00000 00101 001 00000 0001011
= 0x0002900B
```

`qmeas x10, x2`（测量 x2 号比特，结果写入 x10）：

```
funct7=0x00  rs2=0  rs1=2  funct3=0b101  rd=10  opcode=0b0001011
= 0000000 00000 00010 101 01010 0001011
= 0x0001550B
```

## 模拟器扩展实现

[`riscv_emulator_qx.py`](riscv_emulator_qx.py) 是官方 `riscv_emulator.py` 的 fork。

基础部分**行为完全不变**：同样七条指令、同样的标签处理、同样的 1000 步死循环保护、
同样"只返回非零寄存器"的结果字典。测试里有一条专门比对两个模拟器在纯经典程序上的
输出是否逐位一致。

新增部分：
- `encode_instruction(mnemonic, operands) -> int` / `decode_instruction(word) -> (mnemonic, operands)`
  是上面这份文档的可执行形式
- `QuantumUnit` 维护态矢，`qmeas` 真的做坍缩（不是只采样），后续门作用在坍缩后的态上
- 执行扩展指令时，操作数**先过一遍 encode/decode 再执行**。这样编不出来的指令
  也执行不了，文档和实现不会各说各话

## 端到端

[`qx_compiler.py`](qx_compiler.py) 把 Hybrid-QASM 编译成一条融合指令流。
题面那个公开样例编译后是：

```asm
    li x29, 2
    qinit x29
    li x29, 0
    qh x29
    li x29, 0
    qmeas x10, x29        # c[0] 落进 x10
    addi x31, x10, 0      # 经典块从这里读它
    li x30, 1
    bne x31, x30, ELSE_0
    li x31, 100
    ...
```

跑起来：

```bash
python3 starter_kit/qx_compiler.py
python3 -m unittest tests.test_qx_extension -v
```

`r1` 在 `c[0]=1` 时是 105、`c[0]=0` 时是 15，而 `c[1]` 恒等于 `c[0]`——因为经典块
之后那条 `cx` 把两个比特纠缠了，这一步在原来的两段式接口里是表达不出来的。

## 限制

- `qinit` 上限 16 个比特（态矢是稠密的，2^16 个复数已经是纯 Python 的实际边界）
- 角度分辨率 π/1024
- 量子比特下标必须落在 `qinit` 声明的范围内，越界报错
- 同一条门指令不能对同一个比特出现两次
- 继承官方模拟器的 1000 步上限
